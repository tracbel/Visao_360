# Catálogo de funcionalidades do produto Vórtice / Vórtico CRM (o que o fornecedor entrega, canais de entrega e o que o CRM próprio da Tracbel precisa ter em cada fase)

> Pesquisa automatizada - workflow `crm-tracbel-pesquisa-profunda`, 30/08/2026.

## Resumo

O Vórtico CRM (fornecedor Vórtice, Ribeirão Preto) não é "um CRM": é uma suíte CRM+BPM licenciada por MÓDULO, versão 4.04.01, com 11 "sistemas" e 48 módulos registrados no próprio banco (GE_Sistema/GE_Modulo). Os módulos com código de licença são Atendente (CRM_M001), Administrador (M002), Supervisor (M003), Configurador (M004), Modeler (M006), Config RD Station (M007), Cobrança (M010), Web CRM (M020), OUT CRM (M021), JUNO Mobile (M051), Mobile Lite (M052), BPM 2025 (M100), Painel de Controle 2025 (M110), Query Builder (QVW_M001-003), Segurança Global (GLB_M000) e Doc Manager (DMN). A entrega é multi-canal: desktop Gupta/Team Developer (RemoteApp), CRMWeb ASP.NET, API REST wsVorticeCrmApi, dois apps móveis, portal do cliente, Doc Manager sobre FTP e um "Servidor de Processos" (agendador com 71 tipos de job catalogados, incluindo ~25 integrações externas prontas: Conductor, Neurotech, Certiface, Boa Vista, Mail2Easy, AllIn, Méliuz, MktZap, NetPoint, PierLabs, SAP, JD Quote, Google Agenda, Discador Power, URA IVR, AutoAvaliar). O núcleo funcional real é um motor BPM guiado por catálogos (980 ações, 4.208 resultados, 62 modelos de processo, 273 fases, 2.160 mapeamentos resultado→fase/status, 5.958 regras de geração automática de agenda) somado a um construtor de formulários que materializa UMA TABELA FÍSICA POR FORMULÁRIO (175 tabelas IV_Q_* + 175 views IV_Q$*), a um motor de segmentação/RFV/carteira, a um Message Center com 1.341 regras de notificação e a "Objetos Dinâmicos" (196 SQLs gravados no banco) que são o único mecanismo de extensão/low-code. Boa parte do catálogo está PRESENTE mas ZERADA na Tracbel (cartão, F&I, call center/URA, portal, WhatsApp, push, projetos, tags, base de conhecimento) — o produto é vendido como plataforma genérica e cada cliente usa uma fatia. Para o CRM próprio: copiar o modelo conceitual Ação×Resultado×Regra e a segmentação de carteira; evitar a materialização física por formulário, o low-code em SQL solto e o acoplamento a Gupta/FTP/telas Win32.
